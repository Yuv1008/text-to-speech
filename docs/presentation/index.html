Project Presentation

Text to Speech

A full-stack web app that turns typed or pasted text into natural-sounding speech — pick a language and voice, shape the delivery, play it back, and download it.

React 18 + Vite Node.js + Express SQLite Google TTS · ElevenLabs
Yuvraj Goraya · 01 / 16
Why this project

Problem & objectives

Problem statement

Reading large amounts of text isn't accessible to everyone. A text-to-speech tool gives people a second way to consume written information — through audio instead of the page.

Objectives

  • Understand frontend ↔ backend communication over REST
  • Integrate a real text-to-speech service behind a clean API
  • Validate input and handle failure explicitly, never silently
  • Ship a responsive, accessible, production-feeling UI

What it does

Core features

01

Text input

Live character + word count, soft warning at 80%, hard cap at 1000, clear button.

02

Language & voice

9 locales, 12 voices. Voice list auto-resets to match the selected language.

03

Delivery control

Speed (0.5–2.0×) and pitch (‑10..10) sliders with live numeric readout.

04

Generate speech

Disabled on invalid input or in-flight request, inline loading spinner.

05

Custom audio player

Play/pause, seekable scrubber, volume + mute, speed chip, live waveform.

06

Download

Readable filename derived from the source text, proper attachment headers.

07

History

Recent generations in SQLite — replay, delete one, or clear all.

08

Error handling

11 distinct error codes — validation, rate limits, provider & network failure.

05 / 16
Swappable by design

One interface, three providers

TTS_PROVIDER
env var picks the adapter
mock — offline, real playable WAV, zero keys
google — Google Cloud TTS REST
elevenlabs — ElevenLabs REST

Every adapter implements synthesize() and listVoices(). A 4th provider means one new file plus one line in the factory — nothing else changes.

08 / 16
Defense in depth

Security & hardening

🔑

Keys never reach the client

Provider keys live only in server-side env vars.

🛡️

Server never trusts the client

Every field re-validated with zod, regardless of UI checks.

⏱️

Rate limited

10 requests/minute/IP on /api/tts, with Retry-After.

🌐

CORS locked down

helmet + cors restricted to one configured client origin.

🧹

Nothing kept forever

Generated audio auto-deleted after 30 minutes by a janitor sweep.

🚫

No leaked internals

Centralized error handler — no stack traces or provider details ever reach the client.

Honest accounting

Known limitations & next steps

  • MOCKAlways returns WAV regardless of requested format — no codec dependency in the stack.
  • ELEVENLABSNo native pitch control; rate maps to its own speed setting instead.
  • CACHEIn-memory and per-process by design — scoped to the same 30-minute life as the audio files.
  • NEXTPoint at a real provider: set TTS_PROVIDER + a key, restart — nothing else changes.
